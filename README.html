01

为什么要自己做一个素材浏览器

需求并不复杂：电脑连接相机热点，打开一个页面，看见 SD 卡里的照片和视频，挑选后下载。困难在于，相机 Wi‑Fi 并不是一台带后台页面的普通路由器。

最初我也尝试过最直觉的办法：连接相机热点，在浏览器里打开网关地址。结果是没有管理页，也没有可遍历的文件目录。相机的 HTTP 服务确实存在，但它更像一条“已经知道文件路径之后再取文件”的数据通道；在取得有效会话和素材路径之前，单独访问网关没有意义。

官方 iOS SDK 给出了完整的能力轮廓：Wi‑Fi 建连、心跳、文件列表和文件下载都有对应接口。但它以 XCFramework 二进制依赖交付，适合 iOS 工程，不适合直接嵌入桌面 Web 工具。官方文档也明确把“获取文件列表”和“文件下载”列为 Camera SDK 的文件管理能力。于是问题变成了：能否只复现浏览素材所需的最小只读链路？

目标摆脱 App 依赖

相机热点与电脑之间直接通信，不要求手机参与，也不要求互联网。

原则只读优先

不拍摄、不改参数、不删除、不格式化；协议允许列表在发送前硬检查。

交付普通浏览器界面

照片、视频、日期分组、批选、分页和下载都留在熟悉的 Web 交互里。

独立互操作项目

本文记录的是实机流量观察与工程实现，不是 Insta360 对私有协议的官方承诺。相机型号或固件变化可能改变行为。

02

从“网关打不开”到两条并行通道

真正的突破不是找到某个隐藏网页，而是确认控制和文件传输根本不是同一条连接。

STEP 01直接访问网关失败

浏览器没有目录页，常规 HTTP 探测也拿不到素材清单。

STEP 02被动观察原生 App 流量

发现 App 会先连接相机的 TCP 6666 端口，并维持长连接。

STEP 03识别 UCD2 帧与 Protobuf 数据

控制帧以 UCD2 开头，响应负载中可见设备选项与 DCIM 文件路径。

STEP 04固定重放只读请求

不推测写指令，只重放已捕获的命令 8 与命令 13；拿到路径后再访问 HTTP 文件服务。

STEP 05浏览器产品化

用本机 API 持有会话、限制路径、代理 Range 请求，前端只面对清晰的 JSON 和媒体 URL。

一份素材如何来到浏览器CONTROL + DATA

02 · CONTROLTCP 6666 建立会话同步、只读查询、心跳
03 · INDEX解析 DCIM 路径生成精确文件白名单

03

对 UCD2 控制帧的最小理解

捕获到的控制帧以 ASCII 字节 UCD2 开头。当前实现只需要知道怎样划分完整帧、怎样取得内部序列号，以及怎样从响应负载里解析状态与 Protobuf 数据。尾部四字节完整性字段没有被臆测重算，而是保留捕获值。

观察到的帧布局NOT AN OFFICIAL SPEC
Magic4 bytes
UCD2 Version / Type4 bytes
外层元数据 Length4 bytes
little-endian Payload变长
状态、序列号、Protobuf Integrity4 bytes
固定捕获值

为什么坚持固定帧

完整性字段无法从少量样本中可靠归纳。与其“猜一个 CRC 然后试试看”，我选择只保存已经由官方 App 发出、并在实机验证成功的读取帧。这样做牺牲了任意分页参数，却把风险压缩到可以审计的常量集合。

ALLOWED_COMMANDS = {8, 13}

def send_readonly(sock, frame):
    command = inner_request_code(frame)
    if command not in ALLOWED_COMMANDS:
        raise RuntimeError("READ-ONLY policy rejected command")
    sock.sendall(frame)
内部命令在本项目中的用途发送策略
8读取设备、存储等选项信息固定捕获帧
13读取文件列表，固定起点 0 / 100 / 200 / 300 / 400固定捕获帧
其他拍摄、设置、删除、格式化等潜在写操作发送前拒绝

控制连接还需要心跳。官方 SDK 文档同样指出，长时间会话必须持续发送 heartbeat，否则相机会判定连接断开。项目使用固定心跳帧维持只读会话，文件代理则在这个会话存活期间工作。

04

整体架构：浏览器之外，还有三层

网页不能直接打开任意 TCP Socket，也不应该知道相机私有帧。因此 App 把设备协议、文件代理和产品界面分开。

运行时分层LOCALHOST ONLY
macOS App Shell原生 Mach-O 启动器、图标、日志与生命周期；点击网页退出后回收全部子进程。
Web UI · :3000React / vinext 生产构建；日期分组、缩略图、批量选择、分页和媒体预览。
Local API · :8765Python ThreadingHTTPServer；持有相机会话、输出 JSON、代理媒体与 Range。
Camera Control192.168.42.1:6666；UCD2 固定只读帧、响应匹配与心跳。
Camera Files192.168.42.1:80；只访问当前目录响应出现过的精确路径。

为什么不是“纯 Web”

浏览器的安全模型不允许页面随意连接 TCP 6666，也无法绕过跨域规则直接读取相机文件。localhost 服务不是多余的一层：它既是协议适配器，也是安全边界。网页只会调用 127.0.0.1:8765，而 API 只监听回环地址，局域网里的其他设备无法访问。

05

后端关键逻辑

1. 帧读取与请求匹配

后台线程持续从 Socket 读取数据，把黏包与半包整理为完整 UCD2 帧。每个只读请求带内部序列号，响应到达后按序列号唤醒等待者，避免心跳或异步消息干扰当前请求。

frames, buffer, discarded = extract_frames(buffer)
for frame in frames:
    sequence = inner_sequence(frame)
    if frame[6] == 4 and sequence is not None:
        responses[sequence] = frame

2. 文件目录与 500 条边界

应用会先尝试读取相机 HTTP 目录索引。如果固件开放索引，就能取得完整目录，不受固定五页限制。如果目录索引关闭，则降级到五个已验证的 UCD2 分页帧，最多确认前 500 个文件，并在页面上明确显示截断提示。

“分页 300”与“协议 500”是两件事

300 是浏览器每页渲染数量，控制页面性能；500 是降级协议能够确认的最大目录范围。界面分页不会凭空突破相机协议边界。

3. 精确路径白名单

媒体代理不接受任意文件系统路径。每次请求都必须与当前相机目录中的某个字符串完全相等；即使有人手工修改 URL，也不能借代理读取未列出的地址。

def assert_known_path(self, path):
    if path not in self.files:
        raise ValueError("path is not in the current camera file list")

4. Range 转发

视频播放不应先下载完整文件。浏览器发送的 Range 头会被转发给相机，API 再原样回传 206 Partial Content、Content-Range 和长度信息。这样拖动视频时间轴只读取所需片段。

06

让数百个素材仍然像一个正常相册

DATE默认按自然日分组

从文件名提取拍摄时间，按日期倒序；无法识别的文件进入“日期未知”。

BATCH跨页与整日选择

每页最多 300 项，但选择状态独立保存；“选择当天全部”不受当前分页切割影响。

MEDIA视频首帧缩略图

优先匹配同名 LRV 低码率文件，没有代理文件时再从原视频读取首帧。

预览不是“把原文件塞进标签”

点击视频卡片后，播放器优先打开配对的 LRV 代理文件。浏览器原生控制条负责播放、暂停、音量与时间轴，而后端的 Range 转发保证拖到任意时间点时只向相机读取对应片段；下载按钮始终指向原始文件，不会把代理文件误当成成片。

照片载入后会先检查像素比例。接近 2:1 的等距柱状图会进入 360° 查看器：一个 WebGL 片元着色器把屏幕上的每个像素反投影为球面方向，再换算为全景纹理坐标。鼠标或触控拖动改变经纬视角，滚轮调整视场角；普通照片仍使用平面预览。

const ratio = image.naturalWidth / image.naturalHeight;
const panorama = ratio >= 1.8 && ratio <= 2.2;

longitude = atan(direction.x, direction.z);
latitude  = asin(direction.y);
全景查看器不负责拼接

它面向已经是 2:1 等距柱状格式的 JPG/INSP 图像。若相机保存的是双鱼眼原始画面，仍需先用官方软件或独立拼接算法转换，浏览器不能仅靠旋转纹理恢复正确视角。

快速滑动时，为什么骨架必须很轻

一页 300 个卡片如果同时创建视频请求、同时执行 shimmer 动画，会把网络和合成线程一起压满。当前实现让全部卡片立即绘制静态占位，只有距离视口约 1400 像素以内的素材才开始请求，并且只有这批骨架执行动画。

const observer = new IntersectionObserver(onVisible, {
  rootMargin: "1400px 0px"
});

// 进入预取范围后才挂载 img / video
{active && <MediaSource />}

这个策略不追求“所有缩略图尽快下载”，而是优先保证滚动时屏幕上永远先有稳定的几何结构。对相机热点这种带宽有限、延迟偏高的网络尤其有效。

安全不是提示语，而是代码路径

边界实现作用
控制命令允许列表仅含 8、13未知或写命令在 Socket 发送前被拒绝
文件路径当前目录精确白名单阻止路径注入和越权代理
网络监听仅 127.0.0.1其他局域网设备无法调用本机 API
目录完整性截断状态显式展示不把前 500 条伪装成完整目录
进程退出网页 shutdown → API shutdown → 父进程回收相机会话和两个本地端口一并关闭
我刻意没有实现的功能

删除文件、修改参数、拍照、录像、格式化存储卡、同步时间。这些能力与“浏览素材”无关，却会明显扩大误操作面。

签名与公证

当前分发包使用 ad-hoc 签名，适合朋友间研究。通过聊天软件或浏览器下载后，Gatekeeper 可能要求首次右键“打开”。如果要面向公众发布，应使用 Apple Developer ID 对嵌套二进制和 App 签名，提交 Apple 公证，再对分发包 stapling。Apple 官方将公证作为 Developer ID 应用分发的重要检查流程。

09

源码如何继续改

源码包与成品 App 分开。成品强调“拿来就用”，源码包保留前端、协议工具、测试、打包模板、图标和离线 Protobuf 依赖。开发依赖不直接塞进源码 ZIP，避免把 700 多 MB 的 node_modules 当源码分发。

安装开发依赖

创建 Python venv，安装 requirements；进入 web 执行 npm install。

修改功能

页面在 web/app/page.tsx，样式在 globals.css，本地 API 在 tools/insta360_web_server.py。

运行测试

Python 单元测试审计只读约束与解析；前端测试执行生产构建和服务端渲染检查。

重新打包

tools/build_distributions.sh 支持 all、arm64 或 x86_64 三种目标。

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
(cd web && npm install)

.venv/bin/python -m unittest discover -s tests -v
npm --prefix web test

tools/build_distributions.sh all
扩展协议前先扩展证据

不要因为某个 Protobuf 文件名叫 delete_files 就直接调用它。新增任何控制命令前，应先取得官方 App 的真实只读/写入行为样本，确认完整性字段、状态码和失败行为，并重新定义风险边界。

10

App 使用方式

启动相机热点

保持相机唤醒，并完全退出手机上的 Insta360 App，避免两个客户端争用控制会话。

Mac 连接相机 Wi‑Fi

系统提示“无互联网连接”是预期状态，不要切回其他网络。

双击对应架构的 App

M 系列芯片使用 Apple Silicon 版；老款 Intel Mac 使用 Intel 版。

点击“连接相机”

目录读取完成后即可按日期浏览、搜索、批选、预览和下载。

点击“断开并退出”

页面先断开控制会话，再关闭本地 API 和网页服务；无需终端或 Ctrl+C。

朋友第一次打不开怎么办

ad-hoc 签名的 App 经网络传输后可能被 macOS 标记为来自未知开发者。先解压 ZIP，把 App 拖到“应用程序”，然后按住 Control 点击 App，选择“打开”，在确认框中再次选择“打开”。这是没有 Developer ID 公证时的正常限制。

已知边界与下一步

项目当前状态说明
相机型号需要逐机验证固定帧来自当前实机；不同固件可能改变响应或会话行为。
超过 500 个文件条件支持HTTP 目录索引开放时无限制；关闭时降级为前 500 条并提示。
DNG 浏览器预览不支持提供原文件下载，不在浏览器内做 RAW 解码。
360 照片预览支持 2:1 全景自动识别等距柱状图；未经拼接的双鱼眼原片不能直接转换为球面视角。
视频格式兼容依浏览器解码器LRV/MP4 通常可用；特殊编码可能只显示占位并允许下载。
公开分发未公证当前为朋友间研究包；正式发布需 Developer ID 签名与 Apple 公证。

接下来最值得做的不是堆更多按钮，而是积累更多型号与固件样本：验证目录索引差异、命名规则、LRV 配对方式和控制会话超时。只要继续保持“观察先于实现”，这个项目就能扩展，而不会失去最初的安全边界。
